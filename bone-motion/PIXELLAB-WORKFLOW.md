# 기본 자세 원화에서 전투 모션까지 (PixelLab 작업 순서)

2026-11-18 정리. 다른 PC나 다른 Claude 세션에서 이 문서 하나로 이어서 작업할 수 있게 적었다.
모션의 기준은 `MOTION-GUIDE.md`, 폴더와 도구 설명은 `README.md`에 있다.

## 한 줄 요약

장수마다 **정면 기본 자세 그림 1장**을 그린다. PixelLab으로 측면·후면을 만들고, 본의 뼈대를 보내 **전투 대기 자세**로 옮겨 그리게 한 뒤, 그 전투 대기 그림을 시작 그림으로 **이동, 평타 3개, 전법**을 뽑는다.

```
정면 기본 자세 원화 (사람이 그림/생성)
   └─ 1. 8방향 회전        → 측면·후면 기본 자세
        └─ 2. 뼈대 추정     → 각 방향 그림의 관절 위치
             └─ 3. 전투 대기로 옮겨 그리기 (본의 대기 자세 뼈대)
                  └─ 4. 전투 대기 그림 확정 (방향별 1장)
                       └─ 5. 이동·평타·전법 (본의 클립 뼈대, 클립당 15프레임)
                            └─ 6. 묶어서 전투 시뮬레이션에서 확인
```

## 왜 이렇게 하나 (오늘 겪은 일)

1. 처음에는 원화를 **전투 대기 자세 그대로** 3방향 그려 달라고 했다. 본의 전투 대기는 몸을 틀고 발을 앞뒤로 벌리고 팔이 몸 앞을 가로지르는 자세라, 이미지 생성(Codex)이 세 방향을 서로 맞게 그리지 못했다. 겹치는 팔다리를 잘못 그리고, 방향마다 자세가 달라졌다.
2. 무기 길이도 문제였다. 장비 1차 원화는 창이 171px(본 128px)이었고, 2차는 창을 140px로 맞추면서 몸이 129px에서 109px로 줄었다.
3. 그래서 방식을 바꿨다. 원화는 그리기 쉬운 **기본 자세**(몸 정면, 팔을 자연스럽게 벌림, 무기는 한 손으로 옆에 듦. 3D 캐릭터 원화처럼)로 받고, 전투 자세는 PixelLab이 본을 보고 만든다.
4. **본의 전투 대기 자세는 바꾸지 않는다** (사용자 지시). 차렷 자세로 바꾸려던 시도는 되돌렸다.

## 본에서 가져다 쓰는 것

| 필요한 것 | 어디에 있나 |
|---|---|
| 장수가 어느 유형이고 어떤 클립을 쓰는지 | `HERO-MOTIONS.md`, `sim/heroes.js` (유형, 평타 세트 A/B, 전법 클립) |
| 장수별 크기와 무기 길이 | `hero-profiles.json` (무기 길이, 날 크기, 키, 폭) |
| 유형의 전투 대기 자세 | `engine/clips/<유형>.py`의 `GUARD`. 그림은 `out/idle-reference/` |
| 클립의 프레임별 관절 좌표 | `overview.solve(유형, 클립)`이 15프레임의 3D 관절을 돌려준다. 파일로는 `out/<유형>/<클립>-track.json` |
| 3D를 화면으로 | `samto_motion.project(view, 점)` → 256 캔버스의 (x, y, 깊이). view는 `front`, `left`, `rear` |
| 재생 시간, 타격 프레임 | 클립의 `durations`, `impact`, `impact2`, `arrive` |
| 위·아래 공격의 다가서기 | `-track.json`의 `approach` (최대 41px, 프레임별 곡선) |

장수 한 명이 쓰는 클립은 6개다: `idle`, `move`, 평타 3개(`a1 a2 a3` 또는 `b1 b2 b3`), 전법 1개(`s1`~`s6` 중 하나).

좌표 약속: x = 정면에서 화면 오른쪽(캐릭터의 왼쪽이 +x), y = 전방, z = 위. 256×256 캔버스, 접지 기준점 (128, 224), 카메라 고각 18°. 방향은 정면 = PixelLab `south`, 후면 = `north`, 왼쪽 측면 = `west`, 시점은 `low top-down`. 오른쪽은 왼쪽 측면을 좌우 반전한다.

## PixelLab API (문서에서 확인한 것)

API 설명서: `https://api.pixellab.ai/v2/llms.txt`, 전체 규격 `https://api.pixellab.ai/v2/openapi.json`.
모든 생성은 작업 ID를 바로 돌려주고, `GET /v2/background-jobs/{id}`로 끝났는지 본다. `DELETE`로 취소한다.
동시에 10건까지(현재 요금제). 256×256까지.

| 단계 | 엔드포인트 | 넣는 것 | 나오는 것 | 비용 |
|---|---|---|---|---|
| 회전 | `POST /v2/generate-8-rotations-v3` | `first_frame`(정면 그림), `description`, `no_background` | 8방향 그림 | 256×256에서 약 8회분으로 추정 (같은 모델을 쓰는 `create-character-v3`가 `ceil(w*h*8/65536)`) |
| 회전(캐릭터로 저장) | `POST /v2/create-character-v3` | `reference_image`(정면), `n_directions` 4 또는 8, `direction_images`(이미 그린 방향은 그대로 씀) | 캐릭터와 방향별 그림 | 8회분 |
| 뼈대 추정 | `POST /v2/estimate-skeleton` | `image` | 사람 관절 18개 (x, y는 0~1) | 0.1회분 |
| 뼈대대로 다시 그리기 | `POST /v2/animate-with-skeleton-v3` | 아래 표 | 프레임 수만큼의 그림 | 3프레임 2, 8프레임 3, 15프레임 4회분 |

`animate-with-skeleton-v3`에 넣는 것:

| 항목 | 내용 |
|---|---|
| `first_frame` | 시작 그림 (PNG base64, 256×256까지). 결과도 이 크기 |
| `first_frame_keypoints` | **시작 그림이 지금 취한 자세**의 뼈대. 그림과 안 맞으면 투명 배경과 색이 망가진다고 문서에 적혀 있다 |
| `keypoints` | 만들 프레임마다 뼈대 하나씩. 3~15프레임 (rig를 쓰면 1~15) |
| `rig` | 사용자 정의 뼈대. 관절 2~64개, 부모를 먼저 적는다. 무기를 넣을 수 있다 |
| 관절 하나 | `x`, `y` (0~1), `label`, `depth` (0~255, 몸 중심이 128, 클수록 카메라에 가까움), `z_index` |
| `direction`, `view` | `south` / `west` / `north`, `low top-down` |
| `description`, `action` | 생김새(자세가 아니라 외형), 동작 이름 |
| `template_id` | `mannequin`. 네발짐승은 `horse` 등 |

시작 그림의 자세와 만들 자세가 달라도 된다. 문서의 설명이 "그림, 그 그림이 취한 자세의 뼈대, 원하는 프레임의 뼈대를 보내면 그대로 다시 그린다"이다. 그래서 기본 자세 그림에서 전투 대기를 만들 수 있다.

## 단계별 방법

### 0. 기본 자세 원화

- 256×256 PNG, 투명 배경, 발바닥 y=224, 접지 기준점 (128, 224).
- 정면 한 장. 몸은 정면, 두 발은 어깨너비로 나란히, 팔은 몸에서 조금 벌림, 무기는 오른손으로 몸 옆에 세워 듦(방패·활은 왼손).
- **무기 길이는 여기서 정해진다.** PixelLab은 무기 길이를 그림에서 가져오고 뼈대로는 못 바꾼다. 유형 표준 길이와 한계는 `art-in/README.md`의 표. 장비는 140px.
- 몸 크기: 보병 키 124px(상투·투구 제외), 책사 111px, 기마 163px. 장수별 배율은 `hero-profiles.json`.
- 파일: `art-in/<장수 ID>/front.png`.

### 1. 측면과 후면 만들기

`generate-8-rotations-v3`에 정면 그림을 넣는다. 결과 8장 중 서쪽(왼쪽 측면)과 북쪽(후면)을 `art-in/<ID>/side.png`, `back.png`로 쓴다.
돌린 그림에서 무기 길이와 모양이 유지됐는지 잰다(새로 그리는 것이라 달라질 수 있다).

### 2. 뼈대 추정

방향마다 `estimate-skeleton`. 결과는 `art-in/<ID>/estimate-front.json` 등.
몸 뒤로 가려진 손과 팔꿈치는 추정이 틀린다. 그런 관절은 본의 위치를 쓴다(`pixellab.first_frame`이 이미 그렇게 한다).

### 3. 전투 대기로 옮겨 그리기

- `first_frame` = 기본 자세 그림, `first_frame_keypoints` = 2에서 받은 뼈대 + 무기 양 끝(그림에서 잰 좌표).
- `keypoints` = 본의 `idle` 클립 15프레임. 처음 몇 프레임을 "기본 자세 → 전투 대기"로 넘어가는 중간 자세로 넣으면 변화가 한 번에 크지 않아 잘 나올 가능성이 높다. 예: 1~5번은 기본 자세와 전투 대기를 섞은 자세, 6~15번은 전투 대기의 호흡.
- 뼈대는 사람 관절 14개와 무기 양 끝(`weapon butt`, `weapon tip`), 그리고 뿌리 관절 `pelvis`로 된 rig다 (`pixellab.rig`).

### 4. 전투 대기 그림 확정

3의 결과에서 전투 대기가 가장 잘 나온 프레임 1장을 방향마다 고른다. 이 그림이 이후 모든 클립의 `first_frame`이 된다.
그 그림의 뼈대는 본의 `GUARD`를 그대로 쓸 수 있다(PixelLab이 그 뼈대로 그린 그림이므로).

### 5. 이동, 평타, 전법

클립 하나 × 방향 하나 = 호출 1건, 15프레임, 4회분.
`first_frame` = 4에서 고른 전투 대기 그림, `keypoints` = 그 클립의 15프레임 뼈대.
장수 한 명: 6클립 × 3방향 = 18건, 약 72회분. `idle`은 3에서 이미 얻었으면 15건.

### 6. 확인

`engine/pack_sprites.py <ID>`로 묶으면 `sim/battle.html`이 그 장수만 그림으로 그린다(나머지는 본 인형).

## 지금 코드가 하는 것과 아직 안 하는 것

`engine/pixellab.py`

| 명령 | 상태 |
|---|---|
| `balance` | 됨 |
| `estimate <ID>` | 됨 (방향별 뼈대 추정 저장) |
| `animate <ID> <클립> [방향...]` | 됨. 단, **시작 그림이 이미 전투 대기 자세**라고 가정한다 |
| `fetch <ID> [--wait]` | 됨 (프레임 저장, GIF 미리보기) |
| 회전(`generate-8-rotations-v3`) 호출 | **아직 없음** |
| 기본 자세 → 전투 대기 (3단계) | **아직 없음** |
| 전투 대기 그림을 골라 시작 그림으로 고정 (4단계) | **아직 없음** |

**고쳐야 할 핵심 한 가지: 비율 맞추기 방식.**
지금 `pixellab.retarget`은 "본의 대기 자세와 원화의 관절 차이를 관절마다 구해서 모든 프레임에 더하는" 방식이다. 원화가 전투 대기 자세일 때만 맞다. 원화가 기본 자세면 두 자세가 달라서 이 차이가 의미가 없다.
기본 자세 원화에서는 이렇게 바꿔야 한다.

1. 원화의 뼈대에서 **길이**를 잰다: 목~골반, 골반~무릎~발목, 어깨 폭, 위팔·아래팔, 머리 위치.
2. 본의 같은 길이와 비교해 **부위별 배율**을 구한다.
3. 본의 3D 관절에 그 배율을 적용한 뒤 투영한다(다리 길이, 상체 길이, 팔 길이, 어깨 폭). 무기는 손 위치에서 다시 계산한다.

이러면 자세와 상관없이 원화의 비율이 모든 프레임에 일정하게 들어간다. 4단계 이후에는 시작 그림이 본 자세이므로 지금 방식도 쓸 수 있지만, 한 가지로 통일하는 편이 낫다.

장수별 설정은 `art-in/<ID>/pixellab.json`에 둔다: `family`, `description`(영어, 외형만), `actions`(클립별 동작 이름), `weapon_length`, `weapon_grip`, `weapon_mode`, `art_weapon`(방향별 무기 양 끝 좌표).
`weapon_mode`는 `forward`를 쓴다(손이 잡는 자리는 본 그대로, 늘어난 길이는 무기 끝 쪽으로).

## 장비로 해 본 결과 (2026-11-18)

- 전투 대기 자세로 그린 1차 원화(창 171px)로 `a1` 측면을 넣었다. 얼굴·복식·사모 모양이 유지됐고, 당김 → 디딤 → 찌르기 → 버팀 → 거둠이 본대로 나왔다.
- 창이 본보다 길어서 문제가 생겼다. 늘어난 길이를 손 뒤로 보내니 가운데를 잡고 미는 모양이 됐고, 본 길이의 뼈대를 보내도 창은 그림 길이대로 그려져 찌를 때 캔버스 밖으로 잘렸다.
- 결론: **무기 길이는 그림에서 맞춰야 한다.** 보행 창은 140px까지(모든 클립에서 캔버스 안).
- 사용량: 12건 완료, 약 48회분. 진행 중이던 7건을 취소했는데 그 뒤 잔량이 28회분 더 줄어 있었다. 취소한 작업도 과금되는 것으로 보고 제출 전에 확인한다.

## 해 봐야 아는 것

- 기본 자세에서 전투 대기로 **크게 바뀔 때의 품질**. 한 손으로 든 무기를 두 손으로 잡는 변화, 팔이 몸 앞을 가로지르는 겹침.
- 회전으로 만든 측면·후면에서 **무기 길이와 모양이 유지되는지**.
- **기마**. `template_id`에 `horse`가 있지만 기수와 말을 한 그림에서 다루는 것은 시험하지 않았다. 말 다리 관절을 rig에 넣어야 한다.
- `depth`와 `side`(near/mid/far)를 어떻게 줘야 팔다리의 앞뒤가 가장 잘 나오는지. 지금은 깊이 = 128 + 카메라 쪽 거리(px), 정면에서는 왼쪽을 near로 준다.

## 지킬 것

- PixelLab 토큰은 `%USERPROFILE%/.pixellab/api_key`에서만 읽는다. 저장소, 문서, 채팅에 적지 않는다. 다른 PC에서는 그 파일을 새로 만든다.
- 제출 전에 무엇을 몇 건, 몇 회분 넣는지 사용자에게 알린다. 먼저 한 건만 시험한다.
- 본의 전투 대기 자세(`GUARD`)는 사용자 지시 없이 바꾸지 않는다.
- 작업 중에는 커밋·푸시하지 않는다. 사용자가 말할 때 한다.
