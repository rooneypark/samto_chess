## 한 줄 요약

장수마다 **정면 기본 자세 그림 1장**을 그린다. PixelLab으로 측면·후면을 만들고, 본의 뼈대를 보내 **전투 대기 자세**로 옮겨 그리게 한 뒤, 그 전투 대기 그림을 시작 그림으로 **이동, 평타 3개, 전법**을 뽑는다.

```
정면 기본 자세 원화 (사람이 그림/생성)
   └─ 1. 8방향 회전        → 측면·후면 기본 자세
        └─ 2. 뼈대 추정     → 각 방향 그림의 관절 위치
             └─ 3. 전투 대기로 옮겨 그리기 (본의 대기 자세 뼈대)
                  └─ 4. 전투 대기 그림 확정 (방향별 1장)
                       └─ 5. 이동·평타·전법 (본의 클립 뼈대, 클립당 15프레임)
                            └─ 6. 묶어서 전투 시뮬레이션에서 확인
```

## 왜 이렇게 하나 (오늘 겪은 일)

1. 처음에는 원화를 **전투 대기 자세 그대로** 3방향 그려 달라고 했다. 본의 전투 대기는 몸을 틀고 발을 앞뒤로 벌리고 팔이 몸 앞을 가로지르는 자세라, 이미지 생성(Codex)이 세 방향을 서로 맞게 그리지 못했다. 겹치는 팔다리를 잘못 그리고, 방향마다 자세가 달라졌다.
2. 무기 길이도 문제였다. 장비 1차 원화는 창이 171px(본 128px)이었고, 2차는 창을 140px로 맞추면서 몸이 129px에서 109px로 줄었다.
3. 그래서 방식을 바꿨다. 원화는 그리기 쉬운 **기본 자세**(몸 정면, 팔을 자연스럽게 벌림, 무기는 한 손으로 옆에 듦. 3D 캐릭터 원화처럼)로 받고, 전투 자세는 PixelLab이 본을 보고 만든다.
4. **본의 전투 대기 자세는 바꾸지 않는다** (사용자 지시). 차렷 자세로 바꾸려던 시도는 되돌렸다.

좌표 약속: x = 정면에서 화면 오른쪽(캐릭터의 왼쪽이 +x), y = 전방, z = 위. 256×256 캔버스, 접지 기준점 (128, 224), 카메라 고각 18°. 방향은 정면 = PixelLab `south`, 후면 = `north`, 왼쪽 측면 = `west`, 시점은 `low top-down`. 오른쪽은 왼쪽 측면을 좌우 반전한다.

## PixelLab API (문서에서 확인한 것)

API 설명서: `https://api.pixellab.ai/v2/llms.txt`, 전체 규격 `https://api.pixellab.ai/v2/openapi.json`.
모든 생성은 작업 ID를 바로 돌려주고, `GET /v2/background-jobs/{id}`로 끝났는지 본다. `DELETE`로 취소한다.
동시에 10건까지(현재 요금제). 256×256까지.

| 단계 | 엔드포인트 | 넣는 것 | 나오는 것 | 비용 |
|---|---|---|---|---|
| 회전 | `POST /v2/generate-8-rotations-v3` | `first_frame`(정면 그림), `description`, `no_background` | 8방향 그림 | 256×256에서 약 8회분으로 추정 (같은 모델을 쓰는 `create-character-v3`가 `ceil(w*h*8/65536)`) |
| 회전(캐릭터로 저장) | `POST /v2/create-character-v3` | `reference_image`(정면), `n_directions` 4 또는 8, `direction_images`(이미 그린 방향은 그대로 씀) | 캐릭터와 방향별 그림 | 8회분 |
| 뼈대 추정 | `POST /v2/estimate-skeleton` | `image` | 사람 관절 18개 (x, y는 0~1) | 0.1회분 |
| 뼈대대로 다시 그리기 | `POST /v2/animate-with-skeleton-v3` | 아래 표 | 프레임 수만큼의 그림 | 3프레임 2, 8프레임 3, 15프레임 4회분 |

`animate-with-skeleton-v3`에 넣는 것:

| 항목 | 내용 |
|---|---|
| `first_frame` | 시작 그림 (PNG base64, 256×256까지). 결과도 이 크기 |
| `first_frame_keypoints` | **시작 그림이 지금 취한 자세**의 뼈대. 그림과 안 맞으면 투명 배경과 색이 망가진다고 문서에 적혀 있다 |
| `keypoints` | 만들 프레임마다 뼈대 하나씩. 3~15프레임 (rig를 쓰면 1~15) |
| `rig` | 사용자 정의 뼈대. 관절 2~64개, 부모를 먼저 적는다. 무기를 넣을 수 있다 |
| 관절 하나 | `x`, `y` (0~1), `label`, `depth` (0~255, 몸 중심이 128, 클수록 카메라에 가까움), `z_index` |
| `direction`, `view` | `south` / `west` / `north`, `low top-down` |
| `description`, `action` | 생김새(자세가 아니라 외형), 동작 이름 |
| `template_id` | `mannequin`. 네발짐승은 `horse` 등 |

시작 그림의 자세와 만들 자세가 달라도 된다. 문서의 설명이 "그림, 그 그림이 취한 자세의 뼈대, 원하는 프레임의 뼈대를 보내면 그대로 다시 그린다"이다. 그래서 기본 자세 그림에서 전투 대기를 만들 수 있다.

## 단계별 방법

### 0. 기본 자세 원화

- 256×256 PNG, 투명 배경, 발바닥 y=224, 접지 기준점 (128, 224).
- 정면 한 장. 몸은 정면, 두 발은 어깨너비로 나란히, 팔은 몸에서 조금 벌림, 무기는 오른손으로 몸 옆에 세워 듦(방패·활은 왼손).
- **무기 길이는 여기서 정해진다.** PixelLab은 무기 길이를 그림에서 가져오고 뼈대로는 못 바꾼다. 유형 표준 길이와 한계는 `art-in/README.md`의 표. 장비는 140px.
- 몸 크기: 보병 키 124px(상투·투구 제외), 책사 111px, 기마 163px. 장수별 배율은 `hero-profiles.json`.
- 파일: `art-in/<장수 ID>/front.png`.

### 1. 측면과 후면 만들기

`generate-8-rotations-v3`에 정면 그림을 넣는다. 결과 8장 중 서쪽(왼쪽 측면)과 북쪽(후면)을 `art-in/<ID>/side.png`, `back.png`로 쓴다.
돌린 그림에서 무기 길이와 모양이 유지됐는지 잰다(새로 그리는 것이라 달라질 수 있다).

### 2. 뼈대 추정

방향마다 `estimate-skeleton`. 결과는 `art-in/<ID>/estimate-front.json` 등.
몸 뒤로 가려진 손과 팔꿈치는 추정이 틀린다. 그런 관절은 본의 위치를 쓴다(`pixellab.first_frame`이 이미 그렇게 한다).

### 3. 전투 대기로 옮겨 그리기

- `first_frame` = 기본 자세 그림, `first_frame_keypoints` = 2에서 받은 뼈대 + 무기 양 끝(그림에서 잰 좌표).
- `keypoints` = 본의 `idle` 클립 15프레임. 처음 몇 프레임을 "기본 자세 → 전투 대기"로 넘어가는 중간 자세로 넣으면 변화가 한 번에 크지 않아 잘 나올 가능성이 높다. 예: 1~5번은 기본 자세와 전투 대기를 섞은 자세, 6~15번은 전투 대기의 호흡.
- 뼈대는 사람 관절 14개와 무기 양 끝(`weapon butt`, `weapon tip`), 그리고 뿌리 관절 `pelvis`로 된 rig다 (`pixellab.rig`).

### 4. 전투 대기 그림 확정

3의 결과에서 전투 대기가 가장 잘 나온 프레임 1장을 방향마다 고른다. 이 그림이 이후 모든 클립의 `first_frame`이 된다.
그 그림의 뼈대는 본의 `GUARD`를 그대로 쓸 수 있다(PixelLab이 그 뼈대로 그린 그림이므로).

### 5. 이동, 평타, 전법

클립 하나 × 방향 하나 = 호출 1건, 15프레임, 4회분.
`first_frame` = 4에서 고른 전투 대기 그림, `keypoints` = 그 클립의 15프레임 뼈대.
장수 한 명: 6클립 × 3방향 = 18건, 약 72회분. `idle`은 3에서 이미 얻었으면 15건.

### 6. 확인

`engine/pack_sprites.py <ID>`로 묶으면 `sim/battle.html`이 그 장수만 그림으로 그린다(나머지는 본 인형).

**고쳐야 할 핵심 한 가지: 비율 맞추기 방식.**
지금 `pixellab.retarget`은 "본의 대기 자세와 원화의 관절 차이를 관절마다 구해서 모든 프레임에 더하는" 방식이다. 원화가 전투 대기 자세일 때만 맞다. 원화가 기본 자세면 두 자세가 달라서 이 차이가 의미가 없다.
기본 자세 원화에서는 이렇게 바꿔야 한다.

1. 원화의 뼈대에서 **길이**를 잰다: 목~골반, 골반~무릎~발목, 어깨 폭, 위팔·아래팔, 머리 위치.
2. 본의 같은 길이와 비교해 **부위별 배율**을 구한다.
3. 본의 3D 관절에 그 배율을 적용한 뒤 투영한다(다리 길이, 상체 길이, 팔 길이, 어깨 폭). 무기는 손 위치에서 다시 계산한다.

이러면 자세와 상관없이 원화의 비율이 모든 프레임에 일정하게 들어간다. 4단계 이후에는 시작 그림이 본 자세이므로 지금 방식도 쓸 수 있지만, 한 가지로 통일하는 편이 낫다.

장수별 설정은 `art-in/<ID>/pixellab.json`에 둔다: `family`, `description`(영어, 외형만), `actions`(클립별 동작 이름), `weapon_length`, `weapon_grip`, `weapon_mode`, `art_weapon`(방향별 무기 양 끝 좌표).
`weapon_mode`는 `forward`를 쓴다(손이 잡는 자리는 본 그대로, 늘어난 길이는 무기 끝 쪽으로).

## 장비로 해 본 결과 (2026-11-18)

- 전투 대기 자세로 그린 1차 원화(창 171px)로 `a1` 측면을 넣었다. 얼굴·복식·사모 모양이 유지됐고, 당김 → 디딤 → 찌르기 → 버팀 → 거둠이 본대로 나왔다.
- 창이 본보다 길어서 문제가 생겼다. 늘어난 길이를 손 뒤로 보내니 가운데를 잡고 미는 모양이 됐고, 본 길이의 뼈대를 보내도 창은 그림 길이대로 그려져 찌를 때 캔버스 밖으로 잘렸다.
- 결론: **무기 길이는 그림에서 맞춰야 한다.** 보행 창은 140px까지(모든 클립에서 캔버스 안).
- 사용량: 12건 완료, 약 48회분. 진행 중이던 7건을 취소했는데 그 뒤 잔량이 28회분 더 줄어 있었다. 취소한 작업도 과금되는 것으로 보고 제출 전에 확인한다.

## 해 봐야 아는 것

- 기본 자세에서 전투 대기로 **크게 바뀔 때의 품질**. 한 손으로 든 무기를 두 손으로 잡는 변화, 팔이 몸 앞을 가로지르는 겹침.
- 회전으로 만든 측면·후면에서 **무기 길이와 모양이 유지되는지**.
- **기마**. `template_id`에 `horse`가 있지만 기수와 말을 한 그림에서 다루는 것은 시험하지 않았다. 말 다리 관절을 rig에 넣어야 한다.
- `depth`와 `side`(near/mid/far)를 어떻게 줘야 팔다리의 앞뒤가 가장 잘 나오는지. 지금은 깊이 = 128 + 카메라 쪽 거리(px), 정면에서는 왼쪽을 near로 준다.

3. 비율 맞추기를 "부위별 배율" 방식으로 바꾼다.
4. 정면에서 3단계(기본 자세 → 전투 대기)를 한 건 시험한다. 약 4회분.
5. 잘 나오면 세 방향 전투 대기를 확정하고, `a1` 한 클립을 세 방향으로 뽑는다.
6. 괜찮으면 장비의 나머지 클립을 뽑고 `sim/battle.html`에서 촉 5 대 위 5로 본다.
7. 장비가 끝나면 유형별 대표 장수로 넓힌다. 기마는 마지막.

## 지킬 것

- PixelLab 토큰은 `%USERPROFILE%/.pixellab/api_key`에서만 읽는다. 저장소, 문서, 채팅에 적지 않는다. 다른 PC에서는 그 파일을 새로 만든다.
- 제출 전에 무엇을 몇 건, 몇 회분 넣는지 사용자에게 알린다. 먼저 한 건만 시험한다.
- 본의 전투 대기 자세(`GUARD`)는 사용자 지시 없이 바꾸지 않는다.
- 작업 중에는 커밋·푸시하지 않는다. 사용자가 말할 때 한다.


## 2026-11-18 장비 후면 실패 재발 방지 — 이후 요청 전 필수

- 뒤통수를 NOSE로 지정하지 않는다. 실제 보이는 머리 기준점과 숨겨진 얼굴 관절을 구분하고 머리 방향·깊이·가림을 확인한다. 점 이름만 바꾸지 말고 머리띠의 부모, 고정점 좌표와 깊이까지 실제 원화에 다시 맞춘다.
- 정면용 얼굴·눈·수염 유지 지시를 후면에 복사하지 않는다. 방향별 appearance/action 전체를 읽어 서로 모순되는 지시가 없는지 검사한다.
- 입력 이미지 자세와 first_frame_keypoints를 맞춘다. 기본 원화와 선정된 대기 원화의 관절 좌표를 혼용하지 않는다.
- 제출 전에 방향별 입력+본, 목표 프레임별 본, 손/그립·무기·장식 고정점·접지·복귀를 로컬에서 겹쳐 검수한다. 숨겨져 확인할 수 없는 관절은 추정이라고 기록한다.
- 생성 결과도 프레임별 본과 중첩 검수한다. 방향/얼굴만 좋아졌다는 이유로 본 정합 완료라고 말하지 않는다.
- 단일 프레임 튐은 프레임 제외 또는 로컬 보정 가능성을 먼저 검토한다. 자동 유료 재생성 금지. 사용자에게 검수안과 건수·예상 비용을 보여주고 명시적 승인을 받은 뒤 제출한다. 비용 안내만 하고 승인으로 간주하지 않는다.
- 제출 전 기존 job의 상태를 확인하고 중복 제출하지 않는다. 정면/측면/후면 각각 접수·진행·완료·취소 여부를 명확히 구분한다. 마지막 조회와 현재 상태를 혼동하지 않는다.
- 승인된 장비 정면·측면은 서브디자이너 보정본, 후면은 idle-basic-v2/rear. 추가 생성된 정면 v2는 채택하지 않는다. 확정본은 별도 지시 없이 변경하지 않는다.

## 2026-11-19 제출 전 검사 (장비에서 겪은 문제를 코드에 반영)

유료 호출 전에 반드시 돌린다. API를 부르지 않는다.

```bash
python -X utf8 bone-motion/engine/pixellab.py preflight <장수 ID> [클립 ...]
```

```bash
python -X utf8 bone-motion/engine/preflight.py --types
```

결과는 `out/pixellab-preflight/<ID>/report.md`와 클립·방향별 그림(원화 + 시작 관절, 목표 15프레임)이다. 통과해도 생성 그림을 보증하지는 않는다. 알려진 원인만 미리 없앤다.

`pixellab.py`가 이제 자동으로 하는 것:

- 후면 뼈대에는 `NOSE`가 없고 `back of skull`(뒤통수)을 보낸다. 후면 원화는 관절 추정을 하지 않는다(뒤통수를 얼굴로 추정한다).
- 문구를 방향별로 조립한다. `pixellab.json`의 `description`은 어느 쪽에서나 보이는 것만, `face`는 정면·측면에만, `rear_detail`은 후면에만 붙는다. 방향별 고정 문장(후면: 얼굴 안 보임, 카메라 고정)이 뒤에 붙는다. 방향별 동작 문구는 `actions_front` / `actions_left` / `actions_rear`로 따로 줄 수 있다.
- 후면 요청에 얼굴 단어(beard, eyes 등)가 남아 있으면 제출을 거부한다.
- 발끝 관절(`LEFT TOE`, `RIGHT TOE`)을 함께 보낸다.
- 같은 클립·방향에 이미 작업이 있으면 다시 제출하지 않는다(`--again`으로만).
- `side_offset`(px)을 주면 측면 원화와 측면 관절을 함께 옮긴다. 옮긴 뒤에만 0~1로 자른다.

검사가 잡는 것: 후면 원화와 본의 몸통 회전 불일치, 캔버스 밖 관절, 무기 선이 몸통을 같은 깊이로 지나는 프레임, 후면에서 손이 몸 뒤로 완전히 가려지는 프레임(장비 후면 공격 1에서 자루가 사라진 구간과 같다), 뼈대 부모 순서, 기존 작업.

### 후면 전용 본 (`engine/rear.py`, 사용자 승인 2026-11-19)

전투 대기의 가슴 회전이 20°를 넘는 유형(보행 창, 창·방패, 궁, 한손 검, 사슬낫, 쌍무기, 사슬·채찍)은 **후면 요청에서만** 후면 전용 본을 쓴다. 정면·측면의 확정 대기와 모션은 그대로다.

- 몸통 회전을 대기 기준으로 다시 잰다. 대기는 회전 0(완전 후면)이 되고, 대기보다 더 감는 준비 동작은 그 차이만큼만 돈다.
- 손·무기·발 위치는 그대로라 타격점은 유지된다. 어깨를 펴서 손이 자루에 닿지 않으면 무기를 그 어깨 쪽으로 최대 12px 당기고(보행 창 대기 7px, 궁 조준 8px), 그래도 안 되면 그 프레임만 회전을 일부 남긴다. 남긴 양과 당긴 양은 앞뒤 프레임에 나눠 튀지 않게 했다.
- 94클립 모두 손·발 도달과 무기 관통 검사를 통과한다. `python -X utf8 bone-motion/engine/rear.py`로 다시 확인한다.
- 중무기·군령·책사는 원래 본 그대로다. 기마는 몸통 회전이 없어 대상이 아니다.
- 수치 검사만 통과한 상태다. 실제 후면 그림은 장수마다 한 건씩 먼저 뽑아 확인한다.

### 날리는 천 (`streamers`, 사용자 요청 2026-11-19)

장비는 두건 끈이 모션 내내 한 번도 날리지 않았다. 장비는 그대로 확정하고, 이후 장수는 날려야 할 천을 `pixellab.json`에 적는다.

```json
"streamers": [
  {"name": "headband tail", "attach": "head", "root": [-5, -8, 2], "hang": [-3, -10, -12], "sway": 2.5}
]
```

- `attach`: 묶인 관절(`head`, `neck`, `chest`, `pelvis`, `wrist.L` 등). `root`: 그 관절에서 매듭까지. `hang`: 매듭에서 끝이 쉬는 자리(x=캐릭터 왼쪽, y=앞, z=위). `sway`: 대기 중 바람(px).
- **대기에서는 천을 움직이지 않는다** (사용자 결정 2026-11-19). 대기는 숨 쉬는 자세라 몸이 거의 안 움직이는데, 요화 첫 시험에서 2.5px 흔들림을 줬더니 망토 폭이 84→102px로 부풀어 바람 부는 것처럼 보였다. 대기에서는 천이 쉬는 자리에 그대로 붙어 호흡만 따라가고, 문구도 "바람 없음, 흔들림 없음"으로 나간다.
- 몸이 움직이는 클립(이동, 평타, 전법)에서만 날린다. 끝은 손으로 키를 잡지 않는다. 쉬는 자리를 늦게 따라가므로 몸이 움직이면 뒤로 끌리고 멈추면 한 번 넘어갔다 돌아온다. 이동에서는 뒤로 날리며 걸음에 맞춰 펄럭인다. 길이는 늘어나지 않는다.
- 게임용 대기는 전투 대기 프레임만 쓴다. 기본 자세에서 넘어가는 1~4번은 쓰지 않는다(`art-in/<ID>/clips.json`).
- 뼈대에 매듭·중간·끝 세 점이 추가되고, 동작 문구에 "움직임을 따라 날리고 멈춘 뒤 가라앉는다"가 자동으로 붙는다.
- 원화에서 잰 매듭·끝 좌표는 `art_points`에 방향별로 적는다.
- 대상 예: 두건 끈, 머리띠, 깃털 장식, 긴 소매, 옷깃·도포 자락(제갈량), 망토, 허리끈, 말갈기·꼬리. 제출 전 검사가 `streamers`가 없으면 알려 준다.

### 장수마다 다른 평타 조합 (사용자 요청 2026-11-19)

찍어낸 것처럼 보이지 않게, 같은 유형의 장수끼리 평타 세 개가 겹치지 않는다. 모든 평타가 대기에서 시작해 대기로 끝나므로 1타·2타·3타를 A·B 세트에서 따로 고를 수 있다(유형당 8가지, 모자라면 1·2타 순서를 바꿔 16가지). 장수별 조합은 `HERO-MOTIONS.md`와 `sim/heroes.js`의 `attacks`에 있고 `engine/make_heroes.mjs`가 만든다. 장비는 확정본대로 a1 → a2 → a3이다. 대기와 이동은 유형 공통 본이지만 그림·체격·무기·날리는 천이 장수마다 달라진다.

### 기본 자세 → 전투 대기 → 나머지 (코드 반영 2026-11-19)

위쪽 "지금 코드가 하는 것과 아직 안 하는 것" 표는 예전 상태다. 지금은 세 단계가 모두 `pixellab.py`에 있다.

1. `estimate <ID>`: 기본 자세 원화의 정면·측면 뼈대 추정(0.2회분). 후면은 추정하지 않고 정면 추정을 좌우로 뒤집어 쓴다.
2. `animate <ID> idle [방향]`: 시작 그림은 기본 자세 원화, 시작 뼈대는 그 원화의 자세다. 1~4번 프레임에서 전투 대기로 넘어가고 5~15번은 전투 대기의 호흡이다. 방향당 4회분.
3. `pick <ID> <방향> <프레임 번호>`: 그 프레임을 `art-in/<ID>/guard-<방향>.png`로 확정하고, 그 프레임을 그릴 때 쓴 뼈대를 `guard.json`에 남긴다.
4. `animate <ID> <클립> [방향]`: 확정한 전투 대기 그림이 시작 그림이 된다. 확정 전에는 `idle` 말고는 제출되지 않는다.

비율은 몸 전체에 배율 하나를 쓴다(정면 추정의 목~발목 높이 ÷ 본의 같은 높이, `body_scale`로 직접 줄 수도 있다). 접지 기준점 (128,224)을 중심으로 모든 방향·모든 프레임에 같은 배율을 적용한다. 무기 길이는 원화에서 잰 값 그대로다.

장수 설정 예시는 `art-in/liaohua/pixellab.json`(요화)에 있다.

## 전수검사와 일괄 준비 (2026-11-19)

아직 뽑지 않은 장수 전원을 제출 직전 상태로 준비해 두는 도구다. 모두 무료다.

| 순서 | 명령 | 하는 일 |
|---|---|---|
| 1 | `engine/assign_attacks.py` → `node engine/make_heroes.mjs` | 장수별 평타 3개 고르기. 이미 뽑은 장수와 손으로 정한 조합은 `FIXED`에 고정 |
| 2 | `engine/make_configs.py [--force]` | 장수 설정 파일 38개를 표 하나에서 생성. 외형·무기 좌표·날릴 천은 원화를 보고 적은 것 |
| 3 | `engine/fit_canvas.py <ID ...>` | 원화의 무기가 본보다 길어 캔버스를 벗어나면, 방향별로 캔버스 안 배치를 옮겨 맞춘다(`canvas_offset`). 몸은 줄이지 않는다 |
| 4 | `engine/sweep.py` | 전수검사. 장수 × 클립 × 3방향. 결과는 `out/pixellab-preflight/SWEEP.md` |
| 5 | `engine/run_hero.py <ID>` | 준비됨으로 나온 장수를 처음부터 끝까지 제출 |

전수검사는 전투 대기 그림이 아직 없는 장수의 평타·전법도 검사한다(본의 대기를 시작 자세로 가정). 실제 제출 때는 확정한 전투 대기 그림 기준으로 한 번 더 검사한다.

원화의 무기가 캔버스에 아예 들어가지 않는 장수는 본이나 배치로 해결되지 않는다. 원화에서 무기를 줄이거나, 그 장수만 큰 동작을 빼야 한다. 2026-11-19 기준 여포(화극 약 200px), 마초·공손찬(창 약 195px), 서황(도끼 약 168px)이 해당한다. 참고로 조운의 창은 134px, 관우의 월도는 144px이다.

아직 뼈대에 넣지 못한 것: 쌍무기의 왼손 무기와 창·방패의 방패는 관절이 없다. 그림에서 따라오기만 한다. 이 유형의 첫 장수는 대기와 평타 1개를 먼저 뽑아 확인한다.

## 여러 장수 동시에 돌리기와 최종본 올리기 (2026-11-19)

### 여러 장수 동시에 (`engine/run_batch.py`)

PixelLab은 동시에 10건까지만 받는다(그 이상은 429). `run_hero.py`는 한 명씩 돌려서 자리가 비는 구간이 생긴다. `run_batch.py`는 장수 구분 없이 10자리를 계속 채운다. 비용은 같고 시간만 준다.

```
python -X utf8 bone-motion/engine/run_batch.py idle <id> <id> ...             뼈대 추정, 대기 3방향, 12번 프레임 채택, 숨 쉬는 대기
python -X utf8 bone-motion/engine/run_batch.py rest <id> ... [--clips b1]     나머지 클립 (또는 적은 것만)
python -X utf8 bone-motion/engine/run_batch.py finish <id> ...                로컬 정리, clips.json, 미리보기 GIF
```

- 제출 전 검사는 모든 장수에 대해 먼저 돌고, 하나라도 막히면 아무것도 제출하지 않는다.
- 이미 `job.json`이 있는 클립·방향은 다시 넣지 않는다. 끊겨도 같은 명령을 다시 돌리면 이어진다.
- 그 유형의 첫 장수, 또는 무기 처리 방식이 처음인 장수는 `--clips`로 평타 1개만 먼저 넣어 눈으로 본 뒤 나머지를 넣는다.
- 받은 뒤 흠은 재요청 전에 로컬 보정부터 한다. 한 프레임이 번졌으면 옆 프레임으로 바꾸고(사마의 평타 정면 3번), 원본은 `original/`에 둔다.

### 최종본 올리기

그림은 Git에 넣지 않는다(`docs/리소스_올리기_가이드.md`). 순서는 다음과 같다.

```
python -X utf8 bone-motion/engine/finalize_heroes.py     out/pixellab의 재생 프레임만 art-source/motions/v1/<id>/final/로 모은다
python -X utf8 bone-motion/engine/export_hero_clips.py   시뮬레이터가 final 폴더를 읽게 한다
python tools/asset_packs.py pack                         (그림을 뺐으면 --allow-removals)
python tools/asset_packs.py verify
python tools/asset_packs.py publish                      릴리스에 ZIP 올리기. push보다 먼저 한다
git add asset-packs/catalog.json <코드·문서>, commit, push
```

- 올라가는 것은 재생에 쓰는 프레임과 전투 대기 그림(`guard/`)뿐이다. 보정 전 원본, 15장짜리 대기 원본, 미리보기 GIF, 검사 그림은 `bone-motion/out/`에만 있고 올리지 않는다.
- 다른 PC에서는 `restore` 뒤 `finalize_heroes.py --guards`로 전투 대기 그림을 `art-in/<id>/`에 되돌려 놓아야 클립을 더 만들 수 있다.
- 서황의 줄인 원화(`art-in/xuhuang/short-*.png`)는 올리지 않는다. `engine/shorten_xuhuang.py`가 확정 원화에서 똑같이 다시 만든다.
- 확정 여부는 `finalize_heroes.py`의 `APPROVED`에 적는다. 사용자가 "확정"이라고 한 장수만 넣는다.
