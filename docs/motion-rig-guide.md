## 1. 동작을 먼저 정하고 방향별로 투영한다

1. 담당 장수의 가이드에서 포즈 목적, 무기 종류, 쓰는 손, 주동 다리, 상대·목표 위치, 발동/타격 사건을 읽는다. 인게임 동작과 UI용 대기를 구분한다.
2. 카메라가 없는 상태에서 캐릭터 기준 **전방 / 몸 기준 왼쪽·오른쪽 / 위**를 정한다. 모션 차트에 발·손·무기 끝이 어느 축으로 움직이는지 먼저 적는다. 준비 → 힘 모음 → 전진/디딤/발동 → 버팀 → 회수/정착의 사건표를 쓴다. 예외: 쓰러짐은 대기로 되돌리지 않고 끝 자세를 고정한다.
3. 그림상 정면/후면/측면의 점은 따로 맞춘다. 같은 시간에 같은 발이 딛고 같은 손이 쥔다. **화면 거리의 동일함은 조건이 아니다.** 실루엣과 투영이 달라지는 것이 정상이다.
4. 예를 들어 왼쪽을 바라보는 측면에서 **화면 왼쪽은 전방**이다. 그 측면에서 해부학적 왼쪽은 카메라 쪽 깊이다. 장비 함성에서 왼발을 화면 왼쪽으로 밀면 옆 디딤이 전진으로 바뀐다. 전·후면은 좌우로 벌리는 게 보이고, 측면에서는 발 높이 변화 및 앞뒤 겹침/깊이로 읽혀야 한다.

| 동작 축 | 정면 | 왼쪽 측면 | 후면 |
|---|---|---|---|
| 장수 전방 | 카메라 쪽; 단축되고 내려오는 듯 보일 수 있음 | 화면 왼쪽으로 이동 | 카메라에서 멀어짐; 단축되고 올라가는 듯 보일 수 있음 |
| 장수의 해부학적 왼쪽 | 화면 오른쪽 | 카메라 쪽 깊이 | 화면 왼쪽 |
| 위 | 화면 위와 깊이를 같이 확인 | 화면 위 | 화면 위와 깊이를 같이 확인 |

위 표는 장비 예제 카메라 기준이다. 투영을 결정할 땐 실제 원화의 카메라 높이, 몸통 회전 여부, 기준 피벗을 확인한다. 후면·측면에서 가려진 손/발이 어느 해부학적 부위인지 먼저 정하고, 화면상 오른쪽·왼쪽과 혼용하지 않는다.

## 2. 기준 원화에 본을 맞춘다

- 승인된 방향별 256×256 투명 원화에 본을 각각 얹는다. 기준 피벗은 기본 `(128,224)`. 걷기·함성 예제는 세 방향 모두 이 기준이다. 길게 뻗는 승인 평타의 측면만 원화를 **+40px 패딩**해 `(168,224)`를 쓴다. 다른 장수나 동작에 임의 복사하지 않는다. 뷰 비교 시 피벗을 상대 기준으로 맞추고 원본 좌표를 재저장하지 않는다.
- 골반을 루트로 두고 가슴·목·머리, 어깨→팔꿈치→손목, 엉덩관절→무릎→발목→발끝을 연결한다. 망토·옷깃·갑옷은 움직일 장식과 몸통 고정 부위로 나눠서 원화에 있는 것만 넣는다. 모든 이름은 해부학적 좌우로 고정한다.
- 무기는 손잡이, 자루 중간, 뒷끝, 날 연결부, 날·끝을 분리해 표시한다. 사용하는 손이 무기와 따로 움직이지 않도록, 실제 그립점에 붙인다. 양손이면 자루 좌표계에서 두 점을 고정한다. 손을 놓는 동작 자체가 필요할 때만 이탈·재그립을 명확히 설계한다.
- 몸의 두께를 생략하지 않는다. 갑옷 포함 몸통 폭과 앞뒤 부피를 먼저 잡고 손목·팔꿈치·무기 전체 길이가 어떻게 지나가는지 본다. 겹친 2D 좌표는 곧 관통이라는 뜻이 아니다. 진짜 뒤로 가려지는 부분은 가림으로 처리한다. 반대로 관통을 가린 것으로 숨기지 않는다. 갑옷을 피하려고 창을 과하게 띄우는 것도 실패다.
- 정면의 날 끝이 얼굴·손과 한 덩어리가 되거나, 후면의 긴 자루가 하단에 닿으면 출시할 때 문제다. 본점이 범위 안에 있다는 것만으로는 안전하지 않다. 도트 날 폭, 외곽선, 장식의 실제 그림 영역까지 여백을 본다.
- 본을 움직일 때 원화를 매 프레임 새로 센터링하거나 스케일하지 않는다. 화면이 바뀌어도 장수 외형, 팔 다리의 실제 길이, 무기 길이는 그대로다. 투영에 따른 **보이는 길이**만 바뀐다. 긴 장비의 선회 여백이 필요하면 캔버스에서 투명 패딩으로 공간을 확보하고 매니페스트에 피벗을 적는다.

### 2.1 머리띠·옷자락의 고정점과 자유단

| 대상 | 고정할 곳 | 따로 움직일 곳 |
|---|---|---|
| 머리띠/리본 | 머리의 매듭 | 중간과 끝 (몸이 멈춘 다음 살짝 따라오고 가라앉음) |
| 옷깃/갑옷 판 | 목·가슴 봉제선/갑옷 연결부 | 원화에 자유로운 깃 끝이 실제 있을 때만 |
| 옷자락/허리 매듭/술 | 허리·봉제선 | 아래로 떨어진 중간과 끝 |
| 망토/머리카락 | 어깨 걸쇠/뿌리 | 보이는 중간과 끝; 가려진 방향에서 임의 출현 금지 |

뿌리는 본체와 함께 움직인다. 자유단은 대체로 한 박자 늦게 따라가고, 방향이 바뀌거나 멈출 때 반동을 작게 넣은 뒤 가라앉힌다. 길이·폭을 계속 바꾸거나 바람으로 둥둥 뜨게 하지 않는다. 걸을 때와 힘 센 공격의 흔들림 크기를 다르게 한다. 창·팔·갑옷을 스치거나 관통하지 않는지 전 프레임에서 본다. 루프면 마지막과 처음의 위치뿐 아니라 **속도와 방향**도 이어지는지 본다.

## 3. 동작별 핵심 사건과 예제 적용

### 기본 공격: 장비의 허리 높이 찌르기

- 3~4포즈에서 체중을 싣고 조준, 5~6에서 짧고 힘 있게 밀고, 7에서 목표 중앙을 찌른다. 8에서 제동, 9에서 같은 방향으로 거둔다. **7번은 이 예제의 시각적 타격 포즈일 뿐** 다음 장수나 실제 전투의 고정 프레임이 아니다. 인게임 연동 때 실제 판정 시각에 맞춘다.
- 창대는 옆구리 가까운 허리 높이. 오른손이 뒤에서 밀고 왼손이 앞에서 받치며, 팔꿈치가 서로의 자리를 넘어 손이 꼬이지 않는다. 창날은 하나. 측면에선 수평 동작이 또렷하고 전·후면은 원근과 가림을 검수한다.
- 승인된 실제 출력에서도 전면 창날이 작게 뭉쳐 보이는 구간, 후면 창날 가림과 3번 후면 자루 하단 접촉은 확인됐다. 승인본을 임의 교체하지 말고 이 항목을 다음 장수의 **선제 검수 기준**으로 사용한다.

### 걷기: 발 지지가 먼저

- 장비 예제는 12시안: 1번 왼발 접촉 → 체중 싣기 → 반대 발 들기/교차 → 7번 오른발 접촉 → 반대반복. 세 방향 모두 같은 해부학적 발이 같은 박자에 움직인다. 색/발밑 선이 있는 GIF에서 지지발과 들린 발을 구분한다.
- 발과 골반이 동시에 흔들리기만 하면 걷기가 아니라 춤처럼 보인다. 지지발의 접지 기간, 지나는 발의 들림, 골반이 받는 힘, 두 발이 스쳐 지나갈 때 가림을 먼저 맞춘다. 실제 이동 연동 시 스프라이트 중심과 이동 속도도 별도로 맞춰 지면에서의 발 미끄럼을 확인한다.
- 창은 같은 오른손에 붙이고 몸 옆에서 작은 흔들림만 준다. 빈 왼팔은 다리와 반대로 흔든다. 머리띠·옷자락은 작게 늦춘다. 발/팔이 흐릿했던 이전 텍스트 전용 방식은 신규 기본 제작 경로가 아니다.

### 전법: 장판의 함성

- 1~4 대기와 숨 모으기, 5번에 왼발을 **몸 기준 왼옆으로** 한 번 딛고, 6번에 가슴을 펴며 빈 왼주먹을 든다. 7~8 버팀, 9~12 힘 풀고 원래 자세. 디딤이 전진이나 점프로 비치지 않아야 한다.
- 오른손은 창을 몸 옆에 세우고 같은 그립 유지. 지지발과 창 뒷끝 기준을 유지한다. 가슴·주먹·발로 함성의 힘을 표현한다. 상대 타격, 창 휘두르기, 먼지·이펙트는 모션과 분리한다.
- 측면 5번 왼발 발끝: 중립과 접촉 모두 `(118,220)`, 화면 좌우 전진 없음. 깊이만 `151 → 174`로 카메라 쪽에 나가고, 들기/내리기는 화면 Y로 따로 표현한다. 이 깊이값은 예제의 입력 가이드이지 게임 내 거리나 도트 결과 보장이 아니다.
- **복귀에서 몸통을 늘리지 않는다.** 가슴과 골반을 각자 끌어당겨 몸통 길이를 바꾸지 않고, 고정 비율의 상체를 회전·이동시킨다. 목·허리·팔다리의 길이, 원화 장비·비례를 보존하고, 9~12포즈에서 제자리로 돌아가는 동안에도 매 프레임 실루엣을 대조한다. 입력 마지막 자세는 원화에 맞춘다. 가슴을 열기 위해 화면상 높이를 올려도 몸통 신장으로 표현하지 않는다.
- **이 동작의 표정 예외:** 6~7번 함성 순간만 전·측면 입이 작게 열렸다가 9번까지 닫히도록 요청했다. 눈은 뜬 채 유지하고 눈썹·얼굴 폭·턱·수염은 보존한다. 이를 다른 동작의 표정 변경 허용으로 확대하지 않는다. 후면에는 얼굴/입을 새로 그리지 않는다. **실제 출력에서는 입이 열리는 표현이 선명하지 않았다.** 사용자는 그 상태의 최신 세 방향 출력에 승인했으므로 프레임을 손보거나 재생성하지 않는다.


## 4. PixelLab Skeleton v3 요청 작성 및 검증

- 검수된 **같은 방향 원화 1장**과 그 방향의 `rig`, `first_frame_keypoints`, 연속 `keypoints`를 한 요청에 넣는다. `first_frame`의 Base64는 이미지 데이터이지 API 키가 아니다. 실제 예제는 전면 `south`, 왼쪽 측면 `west`, 후면 `north`를 쓴다. 카메라 앵글 `view`는 방향을 뜻하는 `direction`과 별도다. 현재 요청 원형은 ZIP에서 확인한다.
- `rig`: 이름이 유일한 트리, 루트 하나, 부모를 먼저 선언한다. 화면에서 가까운/먼 쪽 지정 `near/mid/far`은 해부학적 이름과 별도. `estimate`는 해당되는 신체 부위만 연결하고, 소품/천은 필요한 이름과 좌표를 별도로 둔다. 가려진 점도 각 열에 같은 이름으로 유지한다.
- 키포인트: X, Y는 0–1 정규화(현재 256 기준 `x_px / 256`, `y_px / 256`), 화면 오른쪽/아래가 증가 방향. 선택값 `depth`는 0–255, 보통 몸 중심이 128이고 **높을수록 카메라에 가까움**. `z_index`는 별도 그리기 순서, 높을수록 위에 그리는 힌트다. 깊이를 무리하게 주면 자동 추정보다 부자연스러워질 수 있으므로 필요한 구간부터 명시하고 실제 결과를 확인한다. 두 값 모두 이미지 출력이 의도대로 나온다는 보장은 아니다.
- 짧은 설명 `action`은 동작의 의도를 보조한다. 고정 카메라, 손 역할, 시작/끝, 투명 배경, 장식/표정 보존을 명시한다. 본을 대신하는 장문 주문으로 해부학이나 궤적을 해결하려 하지 않는다.
- 실행 전 API 문서의 현재 스키마와 사용량 정책을 확인하고, 승인된 프레임·방향만 요청한다. ZIP 해시·프레임 개수·경로만 확인하는 오프라인 검수는 외부 호출이나 크레딧 차감이 없다. 실제 API 형태는 `POST /v2/animate-with-skeleton-v3` 제출 → 받은 `background_job_id` 저장 → `GET /v2/background-jobs/{id}` 조회다. 실행 도구는 계정 전용 비밀 변수로 인증하며 키를 JSON·로그·소스·ZIP에 넣지 않는다. 클릭/전송 동작을 브라우저 인덱스에 넣지 않는다.
- 제출은 유료일 수 있다. 장수/액션/방향/입력 파일 해시/의도한 변형과 이미 저장된 작업 ID를 확인하고, 동일 요청의 상태를 조회한 뒤 재시도 여부를 결정한다. 대기나 타임아웃이 뜬다고 새 `POST`를 반복하지 않는다. 렌더는 작업별로 나와도 묶음 전체에 대한 사용자 승인과는 별개다.

## 5. 바로 쓸 수 있는 검수 차트

| 시점 | 합격 조건 | 실패 시 먼저 고칠 곳 |
|---|---|---|
| 원화와 본을 처음 얹을 때 | 몸·접지·그립·머리띠/깃의 기준이 일치 | 관절 이름, 원화 자체의 앞뒤, 발 피벗 |
| 준비와 체중 이동 | 접지발이 체중을 받고 반대 발/팔이 의도대로 움직임 | 접촉 사건표와 골반/팔 타이밍 |
| 공격·발동·디딤 | 정확한 목표 축, 실제 무기 길이, 같은 손, 관통·잘림 없음 | 장수 축을 다시 정하고 부피/깊이/레이어를 따로 점검 |
| 끝과 루프 | 원화 자세와 자연스럽게 연결 또는 쓰러짐 고정 | 마지막→첫 장, 몸/발/리본의 방향과 속도 |
| 그림 출력 직후 | 요청 포즈가 도트로 읽힘; 얼굴·갑옷·색·무기·원화 비율 유지; 승인된 동작별 입 예외만; 알파와 여백 확인 | 요청 좌표와 PNG의 실제 모양을 비교하여 실패 프레임을 정확히 지목 |
| 리뷰 및 자산 반영 | 전·측·후 동시 GIF, PNG 비교표, 원본 ZIP, 요청 JSON, 검수·승인 상태 기록 | 이전/반려/시안을 승인 경로와 분리; 승인 전 실제 게임/Git 교체 금지 |

출력을 보는 GIF는 자료의 타이밍 예제다. 전투/이동 엔진 타이밍은 담당 엔진에서 따로 맞춘다. 원본 PNG를 덮어쓰거나, 투명 여백을 자른 프리뷰만 보고 원본의 좌표를 추정하거나, 반려 프레임을 승인본처럼 혼합하지 않는다. 요청에 사용한 원화 해시, 포즈별 지연, 방향별 피벗, 사건 프레임, 비밀정보 없는 작업 식별자/사용량, 눈에 띄는 차이, 승인 여부를 함께 남긴다.

## 6. 다음 장수 작업을 시작할 때 복사할 양식

1. `장수 ID / 동작 ID / 변형 / 목표 사건(타격·발동·착지) / 사용하는 손과 발 / 궤적 축`을 먼저 한 줄로 쓴다.
2. 방향별 입력 파일·SHA-256·피벗과 원화에 실제 있는 장식을 적는다. 관절 이름을 정의하고 중립과 2~3개의 주요 포즈를 먼저 맞춰 본다.
3. 타임라인을 확장하면서 공통 사건과 방향별 투영을 분리한다. 예: `포즈, 짧은 이름, ms, 왼발 지지, 오른발 지지, 그립 상태, 무기 목표, 장식 위상`. 발/그립 조건이 다르면 먼저 그 조건부터 고치고 시간을 덜 쓰는 방향에서 임의로 타협하지 않는다.
4. 세 방향 비교 GIF/키 시트/좌표 JSON을 먼저 남긴다. 생성 시 별개 폴더에 원본 PNG + 요청 해시·작업 ID·사용량·검수 결과를 붙인다. 사용자 승인이 난 입력과 출력만 같은 매니페스트 아래 연결한다.

```text
장수 / 동작 / 변형:
원화 파일 / 해시 / 방향 / 피벗:
타임라인(포즈와 ms):
접지발 시간, 그립 상태와 무기 목표:
방향별 투영 차이와 가림:
장식별 고정점 / 자유단 / 지연:
본 GIF / 요청 해시 / 생성 결과 ZIP:
결함과 작업 처리: [본 제작 중 | 본 검토 | 생성 검토 | 승인 | 반려]
인게임 반영 여부와 판정 타이밍:
```
