# 공용 버튼 최종 적용 가이드

2026-11-16 제작 및 공용 렌더러 검수 완료. 사용자 최종 디자인 확인과 릴리스 게시는 별도다.

## 최종 파일

| 역할 | 파일 | 크기 | 원본 분할 | 화면 모서리 |
| --- | --- | --- | --- | --- |
| 주 버튼 | `game/assets/ui-scalable/green-rich.png` | 579×143 | 66px | 28px |
| 보조 버튼 | `game/assets/ui-scalable/blue-rich.png` | 579×143 | 66px | 28px |

두 파일은 로컬 게임 자산 경로에 교체되어 있다. 초록은 실제 전투 시작의 금테·비취색, 남색은 소환의 은테·잘린 모서리를 기준으로 제작했다. image_gen으로 중앙 질감을 정리하고 최근접 축소했다. 원본 alpha를 이진화하여 투명 외곽을 유지했다.

원본 분할 좌표는 x=[0,66,513,579], y=[0,66,77,143]이며 중앙은 447×11이다. 표시 모서리는 941px 아트보드에서 28px이고 화면 배율·DPR을 공용 렌더러가 반영한다. 기본 모서리 사용 시 표시 폭·높이의 최소값은 56px다.

## 연결

`game/assets/ui-scalable/frames.js`의 `green-button`, `blue-button`은 위 파일과 width=579, height=143, slice=66, corner=28을 사용한다. 현재 메타데이터에 반영되어 있다.

```js
import {nineSlice, disposeNineSlices} from './nine-slice.js';
import {initArtPress} from './art-controls.js';

initArtPress(root.closest('.game') ?? root);
await nineSlice(primaryButton, 'green');
await nineSlice(secondaryButton, 'blue');
// 화면을 닫을 때
disposeNineSlices(root);
```

요소의 폭·높이를 레이아웃에서 먼저 지정한다. 기존 `nineSlice(button,'green'/'blue')` 호출은 button=true 기본값을 통해 새 버튼 원화를 자동 선택한다. 패널은 기존 `button:false` 호출을 유지한다. 글자와 아이콘은 별도 DOM 콘텐츠로 올린다. 공용 art-controls.css와 initArtPress가 실제 입력, 원본 alpha 기반 28% 어둡게 하는 눌림, 비활성을 처리한다.

## 재생성 및 검수

최종 재생성 입력은 `art-source/ui-build/v1/button-rich-v2/green-source-v3.png`, `blue-source-v3.png`다. 아래 생성기를 사용한다.

```powershell
node tools/build-rich-buttons.cjs
node tools/verify-rich-buttons.cjs
```

검수 페이지는 `/game/previews/rich-buttons-v2/index.html`이다. 실제 공용 nineSlice/renderNineSlice와 initArtPress를 사용하며 버튼을 직접 눌러볼 수 있다. PNG 복사 없이 게임 자산을 참조한다.

- 2색 × 14크기 × 3배율(941/390/320 기준), 총 84개 렌더의 네 모서리 픽셀 일치
- 모든 크기에서 중앙의 투명 구멍 0개
- 밝은색·남색·대조색 3배경 × 2색, 실제 포인터 눌림 6개에서 투명 외곽 변화 0개와 가시 영역 눌림 누락 0개
- 결과 `test-artifacts/rich-buttons-validation.json`, 전체 비교 `test-artifacts/rich-buttons-review.png`

검수 범위는 공용 버튼 렌더러와 입력이다. 전체 게임 화면의 문구·배치 회귀 검수는 적용 담당자가 진행하는 화면 작업에 포함한다.
