# 리소스 올리기 가이드

2026-11-16 · 사람과 Codex 모두 이 문서를 따른다.

## 한 줄 요약

**그림·영상은 Git에 올리지 않는다.** ZIP으로 묶어 GitHub 릴리스(`assets-v1`)에 올리고, Git에는 목록 파일(`asset-packs/catalog.json`)만 커밋한다.

| 무엇 | 어디에 |
|---|---|
| 코드, 문서, JSON, HTML, manifest | Git (일반 커밋) |
| PNG·WEBP·JPG·GIF·MP4·WAV·ICO | 릴리스 `assets-v1`의 ZIP |
| 어떤 ZIP에 어떤 파일이 있는지와 해시 | Git의 `asset-packs/catalog.json` |
| 릴리스 위치 | Git의 `asset-packs/release.json` |

이렇게 하는 이유: 그림을 Git에 넣으면 고칠 때마다 과거 버전이 이력에 쌓여 저장소가 계속 커진다. 릴리스 파일은 덮어쓰면 이전 것이 사라진다.

## 받을 때

```powershell
git pull --ff-only
python tools/asset_packs.py restore
python tools/asset_packs.py verify
```

- `restore`가 릴리스에서 필요한 ZIP만 내려받아 풀어 준다. 처음에는 약 250MB를 받는다.
- 저장소가 공개라서 내려받는 데 로그인은 필요 없다.
- 직접 고친 그림이 있으면 `restore`는 덮어쓰지 않고 멈춘다. 먼저 `pack` 하거나, 버릴 것이면 `restore --overwrite`(백업 후 덮어씀)를 쓴다.
- `play_game.cmd`와 `npm start`는 시작할 때 `restore`를 자동으로 돌린다.

## 올릴 때 — 순서를 지킨다

```powershell
git pull --ff-only
python tools/asset_packs.py restore      # 1. 최신 상태에서 시작
# ... 그림을 추가·수정·삭제 ...
python tools/asset_packs.py pack         # 2. ZIP과 catalog.json 다시 만들기
python tools/asset_packs.py verify       # 3. 검증
python tools/asset_packs.py publish      # 4. 바뀐 ZIP을 릴리스에 올리기
git add asset-packs/catalog.json <고친 코드·문서>
git commit -m "..."
git push                                 # 5. 목록과 코드 커밋
```

- **4번(publish)을 5번(push)보다 먼저 한다.** 목록만 먼저 올라가면 다른 사람의 `restore`가 "내려받은 ZIP이 목록과 다르다"며 실패한다.
- `publish`는 바뀐 ZIP만 올리고, 목록에서 빠진 ZIP은 릴리스에서 지운다.
- `publish`에는 GitHub CLI 로그인이 필요하다. 한 번만 하면 된다: `gh auth login`
- 그림을 지웠다면 `pack --allow-removals`를 쓴다. 실수로 사라진 것과 구분하기 위해서다.

## 하지 말 것

- PNG·ZIP을 `git add -f`로 강제 추가하지 않는다. `.gitignore`가 막고 있는 것은 의도된 것이다.
- `catalog.json`의 해시를 손으로 고치지 않는다. 항상 `pack`이 만든다.
- 릴리스 페이지에서 ZIP을 손으로 올리거나 지우지 않는다. 항상 `publish`를 쓴다.
- 같은 그림을 두 곳에 두지 않는다. 미리보기 화면은 `game/assets/`나 `art-source/`의 원본을 경로로 가리킨다(복사본을 만들지 않는다).
- 반려본, 중간 프레임, 실험 결과물은 묶음에 넣지 않는다. 최종본만 넣는다.

## 묶음에 들어가는 폴더

`art-source/`, `game/assets/`, `game/previews/`, `design-delivery/` 아래의 그림·영상 파일이 자동으로 분류되어 묶인다. ZIP 하나는 40MiB 이하이고, 넘으면 `-002`, `-003`으로 나뉜다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| `Downloaded archive does not match the catalog` | 누군가 목록만 푸시하고 `publish`를 안 했다. 올린 사람이 `publish`를 실행한다 |
| `Local artwork edits preserved; restore aborted` | 내 PC의 그림이 목록과 다르다. 올릴 것이면 `pack`→`publish`, 버릴 것이면 `restore --overwrite` |
| `Previously packed assets are missing` | 묶여 있던 그림이 사라졌다. 의도한 삭제면 `pack --allow-removals`, 아니면 `restore` |
| `gh release upload failed` | `gh auth status`로 로그인 확인. 저장소 쓰기 권한이 있는 계정이어야 한다 |
| 두 사람이 동시에 그림을 고쳤다 | 나중 사람은 `git pull` → `restore --overwrite`(내 수정은 `.asset-backups/`에 남음) → 자기 수정을 다시 넣고 → `pack` → `publish` → `push` |
