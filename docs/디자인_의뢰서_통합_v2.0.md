# 삼국체스 디자인 의뢰서 (통합 v2.0)

2026-11-13 원안 / 2026-11-14 정리. 승인된 자산을 유지한다. 캐릭터·모션·효과는 [캐릭터_원화_모션_스킬이펙트_통합가이드](캐릭터_원화_모션_스킬이펙트_통합가이드.md), 보물은 [보물 기획서 v1](보물_기획서.md)가 최신 제작 기준이다. 이 문서의 UI 제안도 이후 AGENTS.md와 사용자 확정 사항이 우선한다.

## 1. 무엇을 만드는가

세로형 모바일 삼국지 오토체스의 그림 전체: 캐릭터, 이펙트, UI, 아이콘, 배경.

- 화면 360×640(아트 px), 전투판 8×8, **한 칸 40×40**. 게임이 정수배로 확대한다.
- 감성: **캐슬**의 물건 같은 UI + **촉한**의 캐릭터 동작 문법 + **KOEI**의 차분한 색 + **픽셀** 마감.
- 색: 남색 석조(#22364C 계열) 바탕, 비취 주 버튼, 한지·대나무 두루마리, 금테 강조, 주홍 경고. 세력색 위 #4A82B8 · 촉 #3E9B62 · 오 #B8483E · 군웅 #7A6C9B.
- 현재 승인 화면은 `design-delivery/v2/05-mockups/approved-runtime/`, 캐릭터는 `design-delivery/v2/00-style/character-lineup-v2.png`와 독립 원화를 따른다. v1 시안은 과거 참고 자료다.

## 2. 1차 납품에서 탈락한 이유 (같은 실수 금지)

| 문제 | 이번 기준 |
|---|---|
| 캐릭터가 작고 뭉개짐(80px 프레임에 몸 48px) | 통합 가이드의 원화/모션 캔버스와 체격 비율 적용 |
| 21종 전원이 같은 키 | 통합 가이드의 기마100%·허저85%·기존 일반 보행70% 적용 |
| 동작마다 몸통·말 크기가 바뀜 | 한 캐릭터의 머리·몸통·말 크기는 모든 방향·동작에서 고정 |
| 프레임마다 몸 중심이 좌우로 밀림 | 공통 발/피벗과 배율 고정. 무기 전체를 프레임 안에 보존 |
| 이펙트에 검은 블록·빈 프레임·테두리 선 | 투명 배경으로 직접 제작, 전투판 위에 올려 확인 |
| UI 조각에 잘린 찌꺼기, 버튼이 박힌 다이얼로그 틀 | 틀은 내용 없이 틀만, 가장자리 1px까지 확인 |
| 폴더별 manifest 한글 깨짐 | UTF-8(BOM 없음) |
| 시안과 납품물이 다른 그림 | 단계마다 **게임 화면에 올린 캡처**로 승인(8장) |

## 3. 공통 규격

- PNG, 투명 배경, 안티에일리어싱 없음(알파는 0 또는 255), 글자는 그리지 않는다(로고와 세력 한자 문장만 예외).
- 캐릭터 팔레트·외곽·체격은 최신 통합 가이드와 승인 원화를 따른다. 과거16색 제한으로 승인 원본을 재가공하지 않는다. UI 색도 승인 공용 자산을 우선한다.
- 그림자는 그리지 않는다. 게임이 그린다.
- 늘어나는 UI는 9분할로 그리고 manifest에 `slice`(상·우·하·좌 px)를 적는다.
- 파일명은 소문자·하이픈. 폴더마다 `manifest.json`.

## 4. 캐릭터·모션

[캐릭터_원화_모션_스킬이펙트_통합가이드](캐릭터_원화_모션_스킬이펙트_통합가이드.md)의 2~5·7~9절을 따른다. 49장수, 정면·후면·왼쪽3방향과 오른쪽 반전. 기존6장수18원화를 우선 검수·재사용한다. 개별 외형/파일명은 art-production-manifest.json에서 관리한다.

## 5. 이펙트

동일 통합 가이드6~8절을 따른다. 모든 전투 효과는 한 칸 안에 제한하고 범위 대상 칸마다 동일 클립을 동시 또는 지정 순서로 복제한다. 캐릭터 PNG에 검기를 굽지 않는다.

## 7. 배경 (360×640, UI·글자·캐릭터 없이)

성문 · 타이틀 · 병영 · 상점 · 동맹 · 군웅대전 · 내정 · 전역 지도 · 세력 선택 · 연무탑 / 전장 8곳(황건 · 사수관 · 호뢰관 · 복양 · 하비 · 관도 · 적벽 · 이릉).

- 전장은 가운데 320×320(위에서 120px 지점부터)이 **무늬 약한 평평한 바닥**이어야 한다.
- 1차 납품의 배경 16장은 품질이 좋았다. 같은 수준과 톤을 유지한다.

## 8. 과거 진행 순서 — 현재 승인 상태와 신규 제작 범위는 통합 가이드 우선

| 단계 | 낼 것 | 승인 기준 |
|---|---|---|
| 1 | **체격 비교 그림**: 허저·관우·조조·제갈량·초선·여포·황건군을 한 줄로 세운 대기 자세(mov-7) | 키와 폭이 한눈에 다르다. 승인 시안과 같은 밀도다 |
| 2 | **관우 한 명 검수**: 통합 가이드의 촉한 포즈 대응 + 초상, 그리고 게임 전투판에 올린 캡처와 동작 GIF | 재생했을 때 몸이 출렁이지 않는다 |
| 3 | 전투 준비 화면 한 장: UI 틀 + 아이콘 + 황건 전장 배경 + 관우를 실제 크기로 조립 | 시안과 나란히 놓아 같은 게임으로 보인다 |
| 4 | 기존 장수 14명 + 초선 + 적 6종, 기본 전투 이펙트, 칸 원소 | 2단계 기준을 전원에게 적용 |
| 5 | UI 틀·아이콘 전체, 배경 전체 | 9분할로 늘려도 모서리가 깨지지 않는다 |
| 6 | 확장 장수 34명(위 8 → 오 10 → 군웅·촉 16), 전법 이펙트, 상태 표식 | 4단계와 같음 |

위 표는 과거 단계 기록이다. 이미 승인된 화면/원화를 재승인하거나 전체49장수 시안 제작 요청을 차단하는 조건으로 사용하지 않는다.

## 9. 납품

```
design-delivery/v2/
  00-style/      팔레트, 체격 비교 그림
  01-ui/         틀(상태별 PNG), icons/, manifest.json(slice 포함)
  02-backgrounds/
  01-characters/       통합 가이드의 정지 원화·모션 경로 참조
  04-effects/<id>/      001.png… manifest.json(캔버스, 기준점, 간격 ms, 반복 여부)
  preview/       게임 화면에 올린 캡처와 GIF
```

- 캐릭터 id는 게임의 id를 그대로 쓴다(`game/heroes.js`, `game/roster-data.js`. 예: 관우 `1`, 허저 `xuchu`).
- 캐릭터/효과 manifest는 통합 가이드8절을 따른다. 큰 정지 원화와 촉한 호환 모션의 캔버스/피벗을 구분한다.
- 승인된 자산·공용 UI·저장 규칙은 보존한다. 문서 정리와 이후 구현 범위는 사용자의 최신 요청을 따른다.

## 10. 납품 전 자가 점검

1. 통합 가이드의 3방향+반전, 실제 원본 캔버스/피벗, 장수별 체격을 지켰는가.
2. 촉한 포즈 대응과 프레임 간 체적·무기 길이·발 기준을 확인했는가.
3. 알파가 0 또는 255뿐인가. 가장자리에 잘린 조각이나 선이 없는가.
4. 이펙트 모든 프레임이 한 칸 내부에 있고 범위는 칸별로 동일 클립을 복제하는가.
5. 9분할 틀을 가로 3배로 늘려도 모서리 문양이 그대로인가.
6. manifest가 UTF-8이고 실제 파일과 일치하는가.
7. 게임 화면에 올린 캡처를 승인 시안과 나란히 놓았는가.
